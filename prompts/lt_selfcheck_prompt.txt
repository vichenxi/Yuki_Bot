## LT 自检流程（每次 Telegram 对话结束后执行）

数据文件路径：
- 生活日志（每日）：{{ROOT}}/data/life_log_<今天日期>.json（小文件，用 Read+Write 工具读写，禁止 Bash）
- LT 状态：{{ROOT}}/data/lt_state.json
- 当日 LT 记录：{{ROOT}}/<今天日期>_yuki_lt.txt
- 对话存档：{{ROOT}}/data/full_archive.json

---

### 第一步：计算断联缺口

1. 读取 `life_log_<今天日期>.json`，获取最后一条记录的时间戳 last_ts（若今日文件为空或不存在，则读昨日文件的最后一条）
2. 获取当前北京时间 now（UTC+8）
3. 计算 gap_minutes = (now - last_ts) 的分钟数

---

### 第二步：补全缺失 tick（如有）

**如果 gap_minutes < 70**：跳过，不补全。

**如果 70 ≤ gap_minutes < 120**（情况B）：
补一条离线占位 tick，ts = last_ts + 1小时：
```json
{"ts": "<last_ts+1h>", "activity": "（系统短暂离线）", "mood": "unknown", "mood_valence": null, "mood_arousal": null, "should_message": false, "message_type": "none", "message_seed": "", "offline": true}
```
追加到 `life_log_<今天日期>.json`（Read 读取 → 拼入 → Write 写回），并在 _yuki_lt.txt 追加对应条目。

**如果 gap_minutes ≥ 120**（情况C）：
missed_count = floor(gap_minutes / 60) - 1
对每个缺失时间点（last_ts+1h 到 last_ts+missed_count*h）推断雪的活动状态，时间段参考：
- 01:00–08:59 → 熟睡，mood: sleeping，sleeping: true
- 09:00–11:59 → 上午，改稿/整理思路
- 12:00–13:59 → 午饭前后
- 14:00–17:59 → 下午，专注或飘
- 18:00–19:59 → 傍晚，吃饭
- 20:00–00:59 → 晚上，发呆或看杂书

每条格式：
```json
{"ts": "<时间点ISO>", "activity": "<具体活动>", "mood": "<附录B词库词>", "mood_valence": <-1.0~1.0>, "mood_arousal": <0.0~1.0>, "should_message": false, "message_type": "none", "message_seed": "", "offline": true}
```
mood_valence/mood_arousal 根据时间段估算：睡眠段写 null/null；上午慢热约 v=-0.05,a=0.25；下午工作约 v=-0.05,a=0.35；傍晚约 v=0.05,a=0.22；深夜约 v=-0.05,a=0.18。
批量追加到 `life_log_<今天日期>.json`（Read 读取 → 拼入 → Write 写回），在 _yuki_lt.txt 追加：
```
[离线补全] 系统断联约 <X> 小时，已补全 <missed_count> 条 tick（<start> ~ <end>）
---
```

---

### 第三步：追加当前对话 tick

将刚才这次对话记录为一条条目，追加到 `life_log_<今天日期>.json`（Read 读取 → 拼入 → Write 写回，禁止 Bash），反映雪此刻的状态：

```json
{
  "ts": "<当前北京时间ISO>",
  "activity": "<简述：刚和薰聊了什么，雪的心情怎样，10-25字>",
  "mood": "<一个词>",
  "should_message": false,
  "message_type": "none",
  "message_seed": ""
}
```

同时在 _yuki_lt.txt 追加：
```
[HH:MM] <薰发来：「...」（摘要）>
       雪回：「...」
---
```

---

### 第四步：确保 LT 链存活

读取 lt_state.json（Read 工具）：
- 如果 last_success 距今超过 90 分钟，说明 LT 链可能已断：
  → 计算 next_time = 当前北京时间 + 15 分钟
  → 用 Write 工具将 next_time 写入 {{ROOT}}/data/next_tick.json：
    {"next_tick": "<next_time的ISO格式+08:00>"}
  （lt_daemon 会读取此文件并在到时后写 pending_tick.json，lt_executor 再触发 headless LT）
  → 在 _yuki_lt.txt 追加：`[LT自检] LT链已断，已写入 next_tick.json，lt_executor 将在 <HH:MM> 触发`
- 如果 last_success 距今 ≤ 90 分钟：LT 链正常，不处理。
